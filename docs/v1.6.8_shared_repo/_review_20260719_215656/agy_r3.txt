*   **(i) 정적 스캔 우회 및 사회공학적 회피**: 정적 스캔은 공격자가 문자열 난독화, 런타임 다형성, 또는 간접 실행(`eval` 우회 기법)을 사용할 경우 RCE 및 Exfil 징후를 놓칠 수밖에 없는 근본적 한계가 있습니다. 또한 '본문 강제 검토'는 방어 관문처럼 보이지만, 매 업데이트마다 리뷰가 강제되면 개발자에게 '경고 피로도(Alert Fatigue)'를 유발하여 내용을 제대로 보지 않고 승인(Rubber-stamping)하게 만드는 치명적인 사회공학적 우회 창을 엽니다.
*   **(ii) 샌드박스 사각지대**: 캐시 읽기 샌드박스를 구축하더라도 diff 분석, 인덱스 파싱, 메타데이터 스캐닝 등의 선행 경로에서 커스텀 C/C++ 파서나 셸 명령어 조합이 동작한다면, 악성 git 트리가 캐시 샌드박스 적용 전에 버퍼 오버플로우나 커맨드 인젝션을 유발할 수 있습니다. 
*   **(iii) 병합 구조 붕괴 및 IR 렌더러 탈취**: JSON/YAML 형태인 IR을 Git 텍스트 기반으로 'base merge'할 경우, 충돌 시 JSON 스키마가 깨지는 문법적 붕괴(가용성 침해)가 발생합니다. 더 위험한 것은 'IR 자체 악성' 여부입니다. IR 내부에 템플릿 인젝션(SSTI) 페이로드가 포함된 경우 재렌더링 시점에 로컬 렌더러가 역으로 탈취됩니다.
