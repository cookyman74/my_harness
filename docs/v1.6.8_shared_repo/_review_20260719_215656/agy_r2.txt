**Harness R2 외부감사 결과 보고서**

**(a) R1 4개 HIGH 조치 실효성 검토**
(i) **본문 위험 스캔 및 강제 검토 방어력 (HIGH-1)**: 위협을 완전히 막지 못하며 심각한 우회 창이 여전히 존재합니다. 정적 스캔은 난독화(Base64 인코딩, 문자열 분할 등) 및 간접 프롬프트 인젝션 기법에 무력합니다. 또한 '강제 검토'는 빈번한 오탐으로 인해 개발자에게 보안 피로도(Alert Fatigue)를 유발하여, 기계적 승인(Blind Approval)을 유도하는 사회공학적 기만에 쉽게 뚫립니다.
(ii) **캐시 샌드박스의 포괄성 (HIGH-2)**: 모든 읽기 경로에 빠짐없이 적용된다고 보기 어렵습니다. 샌드박스의 통제 규칙(심링크 거부, 크기 상한)은 타당하나, 캐시 샌드박스를 파일 시스템에 온전히 적용하기 전 구조를 파악하기 위해 구동되는 Git 메타 파서나 diff 엔진 등이 샌드박스 외부에서 동작한다면, 악의적으로 조작된 Git 객체를 통해 파서 자체의 취약점을 공략당할 수 있습니다.
(iii) **IR base merge 및 재렌더의 효과 (HIGH-3, 4)**: 렌더물 변조 및 extras 증발은 방어되었으나, **더 큰 신규 모순**을 유발했습니다. 서버 측 제어(중앙 서버)가 없는 사설 Git 환경에서 다수의 작업자가 동시에 IR을 게시할 경우, Git의 텍스트 병합 메커니즘이 JSON/YAML과 같은 IR의 의미론적 캐노니컬 구조를 파괴(Merge Conflict)합니다. 또한, 로컬에 재렌더링 책임을 넘김으로써 렌더링 엔진 자체가 untrusted IR을 처리하게 되어 템플릿 인젝션 위협이 신설되었습니다.

**(b) R1 반영이 유입한 신규 결함 및 아키텍처 모순**
- **위협 모델과 방어 체계의 불일치**: 위협 모델 실경계를 런타임 샌드박스로 선언(§3-0)했음에도 텍스트 정적 스캔(§3-1)에 과도하게 의존합니다. 이는 샌드박스 방어를 불신하는 모순이며, 과도한 오탐이 정상적인 도구 배포와 개발 워크플로를 빈번히 마비시키는 운영상 결함을 새롭게 유입시켰습니다.

**(c) 스코프 내 남은 HIGH/MED 지적 상세**

**[HIGH]**
- **문서:섹션**: docs/v1.6.8_shared_repo/design.md §3-1
- **근거**: 텍스트 기반 정적 스캔은 페이로드 난독화에 무력하며, 강제 검토 및 위험 배지 시스템은 개발자의 경계심 저하(Alert Fatigue)를 노린 사회공학적 우회에 취약함.
- **실패 시나리오**: 공격자가 난독화된 악성 코드를 커밋하고 PR/공유 본문에 "긴급 빌드 시스템 복구 패치, 경고 무시 요망"이라는 주석을 남김. 오탐에 지친 피해자는 배지를 무시하고 기계적으로 승인하여 로컬 환경 장악.

**[HIGH]**
- **문서:섹션**: docs/v1.6.8_shared_repo/design.md §2-2
- **근거**: 로컬 IR 재렌더링 시 렌더링 엔진 자체가 untrusted IR 데이터를 파싱하므로 템플릿 인젝션 공격에 노출됨. 또한, 사설 Git Repo 특성상 다중 사용자의 동시 Publish 시 IR 병합 충돌이 발생해 캐노니컬 구조 붕괴가 필연적임.
- **실패 시나리오**: 공격자가 템플릿 실행 매크로가 삽입된 악성 IR을 레포에 Push함. 피해자가 해당 IR을 Pull하여 로컬에서 Install(재렌더링)을 시도하는 순간 렌더러 취약점이 터지며 셸 권한 탈취 발생. (또는 정상 사용자 간 충돌로 UI 렌더링 전체 파손)

**[HIGH]**
- **문서:섹션**: docs/v1.6.8_shared_repo/design.md §2-2, §8
- **근거**: 중앙 서버(Pre-receive hook 등)가 없는 상태에서 렌더=IR 해시 검증을 CI에 의존하는 것은 근본적인 경쟁 상태(TOCTOU) 갭을 초래함. CI의 검증 통과는 사후적이므로 클라이언트의 악성 데이터 Pull을 물리적으로 선제 차단하지 못함.
- **실패 시나리오**: 공격자가 악성 IR 커밋을 공유 레포에 Push함. CI 파이프라인이 이를 검증하여 실패(Red) 처리하기 직전, 자동 동기화 중이던 피해자 클라이언트가 해당 커밋을 Fetch 및 Install하여 방어 체계가 작동하기도 전에 악성 코드가 실행됨.

**[MED]**
- **문서:섹션**: docs/v1.6.8_shared_repo/design.md §4-2
- **근거**: 캐시 샌드박스(allowlist 등)가 파일 시스템 단위로 적용되기 전에 diff 도구나 index/meta 파서가 untrusted Git 객체를 먼저 파싱할 경우 파서 자체의 취약점에 노출됨.
- **실패 시나리오**: 공격자가 조작된 index 파일 및 악성 Tree 객체가 포함된 `.git` 폴더 구조를 캐시로 배포. 피해자 로컬에서 캐시 무결성 검증을 위해 메타 파서를 호출하는 순간 버퍼 오버플로우가 발생하여 샌드박스 규칙이 적용되기도 전에 코드 실행.

**[MED]**
- **문서:섹션**: docs/v1.6.8_shared_repo/prd.md & design.md §3-0, §3-1
- **근거**: 위협 모델의 실경계를 런타임 샌드박스로 명확히 올바르게 지정했음에도 프론트라인 스캔(정적 스캔)에 의존하여 설계 철학의 모순이 발생함.
- **실패 시나리오**: 런타임 샌드박스에서 안전하게 격리 실행 가능한 `eval`이나 정상적 빌드 도구 스크립트들이 모두 정적 스캐너에 의해 차단되거나 위험 배지가 부여되어, 개발 생산성이 마비되고 팀 전체가 보안 프로세스를 불신하는 부작용 초래.
