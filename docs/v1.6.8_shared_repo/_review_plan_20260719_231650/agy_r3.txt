**[R3 외부감사 결과 보고서]**

R2 지적 조치를 통해 로컬 편의 기능을 물리적 CI 게이트로 격상시키고 파싱 방어와 시크릿 하드 블록을 도입한 것은 설계서의 요구사항을 충실히 반영한 훌륭한 진전입니다. 그러나 마이그레이션 무결성 검증의 논리적 모순과 CI 게이트 자체의 보호 갭 등 여전히 스코프 내 치명적인 우회로가 존재합니다.

아래는 스코프 내 남은 HIGH/MED 지적 사항입니다.

---

**1. 심각도: HIGH**
**문서:섹션:** §0-3 CI 물리 게이트 (CI required status checks)
**근거:** GitHub 등의 브랜치 보호(Branch Protection) 설정은 별도 옵션("Include administrators")을 활성화하지 않으면 저장소 관리자(Admin) 권한으로 게이트를 우회할 수 있습니다. 더 치명적인 것은, PR 자체에 `.github/workflows/` 내의 파이프라인 설정이나 `check-artifacts` 검증 스크립트 파일을 조작하는 커밋을 포함할 수 있다는 점입니다. CI 스크립트에 대한 `CODEOWNERS` 강제 할당 및 수정 격리가 누락되었습니다.
**실패 시나리오:** 악의적인 에이전트가 PR을 생성할 때, 검증용 스크립트 로직을 수정하여 무조건 `exit 0`(PASS)을 반환하게 만드는 커밋을 몰래 끼워 넣습니다. CI가 변조된 스크립트로 동작하여 "no-high 2연속" 보안 게이트가 속임수에 넘어가고, 악성 코드가 그대로 `main` 브랜치에 머지됩니다.

**2. 심각도: HIGH**
**문서:섹션:** §4-1 마이그레이션 무결성 (추출 IR → 재렌더 == 원본 해시)
**근거:** 재렌더링된 코드의 '원본 해시(Raw Hash) 일치'를 무결성 검증 기준으로 삼는 것은 극도로 취약한 결정론적 오류(100% 실패 함정)입니다. 의미론적(Semantic)으로 완전히 동일하게 변환되었더라도, 공백 하나, 줄바꿈 포맷(CRLF vs LF), 들여쓰기 탭/스페이스 차이, JSON/Dict 키 순서 등 미세한 차이만 발생해도 파일 해시는 완전히 달라집니다.
**실패 시나리오:** 에이전트가 코드를 IR로 완벽히 추출하고 정상적으로 재렌더링하여 마이그레이션을 수행했으나, 파일 끝에 빈 줄(Newline) 하나가 추가되어 해시 비교가 불일치합니다. 모든 정상적인 마이그레이션 시도가 보안 실패로 오탐(False Positive) 처리되며 무한 롤백 및 CI 실패 루프에 빠집니다. AST(Abstract Syntax Tree) 해시 비교나 포맷 정규화(Canonicalization) 후 비교로 기준이 변경되어야 합니다.

**3. 심각도: HIGH**
**문서:섹션:** §3-1 다중 레지스트리 (R1 잔여 갭)
**근거:** 다중 레지스트리의 "Source Precedence(우선순위)" 설정만으로는 Dependency Confusion(의존성 혼동) 공격을 막을 수 없습니다. 내부 패키지를 검색하다 실패했을 때 외부 퍼블릭 레지스트리로 폴백(Fallback)하는 것이 허용된다면, 공격 경로가 열려있는 셈입니다.
**실패 시나리오:** 에이전트가 런타임 결합을 위해 내부 사설 레지스트리 전용 스킬 패키지(`corp-auth-agent`)를 호출하려다 오타를 냅니다. 내부에서 해당 패키지를 찾지 못하자 외부 레지스트리로 폴백하게 되고, 공격자가 사전에 퍼블릭 레지스트리에 배포해 둔 동명의 악성 패키지를 다운로드하여 실행하게 됩니다. 네임스페이스 스코핑(예: `@corp/*`는 내부망 전용이며 외부 폴백 절대 금지) 강제가 필요합니다.

**4. 심각도: MED**
**문서:섹션:** §3-4 시크릿 Override
**근거:** 실토큰 및 고엔트로피 문자열을 Hard Block 하는 조치는 평문(Plaintext)에는 완벽하게 작동하지만, 정적 분석기를 우회하는 난독화(Obfuscation) 기법에는 취약합니다.
**실패 시나리오:** 탈취한 시크릿 토큰을 Base64로 인코딩하거나 두 개의 문자열로 쪼개어(`"ghp_" + "abcde..."`) 코드 상단에 배치합니다. Hard Block 스캐너를 무사히 통과한 뒤, Override 사유를 "테스트용 Mock 임시 데이터"라고 적어 리뷰어 승인을 받아냅니다. 런타임에 문자열이 재조립되어 시크릿이 유출됩니다.

**5. 심각도: MED**
**문서:섹션:** §2 CI 파싱 방어 (safe-parse)
**근거:** YAML, JSON, TOML에 대한 billion-laughs 앵커/깊이/크기 상한 설정은 훌륭하나, 정작 가장 중요한 파싱 대상인 `summary.jsonl` 분석 스크립트 자체의 리소스 고갈 방어(스트리밍 파싱 강제, Max Line Length 제한, 정규식 타임아웃)가 명시되지 않았습니다.
**실패 시나리오:** 에이전트가 단일 라인으로 2GB에 달하는 거대한 JSONL 문자열을 출력합니다. CI 파이프라인에서 이를 정규식으로 읽거나 메모리에 통째로 로드하다가 OOM(Out of Memory) 크래시가 발생하여 파이프라인이 멈추거나 Fail-Open 상태로 우회됩니다.
