**선검증(Feasibility Spike) R1 외부감사 결과서**

**[ (a) 판정 타당성 관점 ]**

*   **심각도(HIGH)** | docs/v1.6.8_shared_repo/working_history/preflight_20260720_001500.md : P-1 스킬
    *   **근거**: P-1과 P-2는 전체 기능의 타당성 관문(Gateway)임에도 불구하고, 이종 런타임에서의 '라이브 로드(실제 메모리/컨텍스트 인젝션)'를 실증하지 않고 단순 파서 구조 수용만으로 "GO" 판정을 내린 것은 과도합니다. 이는 "가정 위 구현 금지"라는 대전제를 정면으로 위반한 것입니다. 과거 레퍼런스(F13)를 근거로 S0에서 재확인하겠다는 것은 선검증의 존재 의의를 부정하는 행위입니다.
    *   **실패 시나리오**: S0(본 구현) 진행 중 특정 런타임(예: 제미나이/코덱스)에서 파싱된 SKILL.md 데이터를 프롬프트나 샌드박스 룰로 변환하여 적용할 때 치명적인 호환성 에러나 컨텍스트 유실이 발생. 결국 기초 설계로 회귀해야 하는 대규모 매몰 비용(Sunk Cost) 발생.

*   **심각도(HIGH)** | docs/v1.6.8_shared_repo/working_history/preflight_20260720_001500.md : P-4 캐시 샌드박스
    *   **근거**: `core.symlinks=false` 설정은 Git checkout 시 워킹 트리 내의 심링크를 일반 텍스트 파일(타겟 경로 포함)로 인스턴스화하여 임시 무력화할 뿐, 완전한 보안 방어책이 아닙니다. 에이전트 내의 빌드 스크립트나 런타임 도구가 해당 텍스트를 읽어 심링크로 재복원할 수 있으며, Directory Traversal(`../`)이 포함된 텍스트를 파일 I/O로 직접 참조하는 등의 2차 공격 벡터에는 무방비입니다. `.git` 폴더 내부 변조(예: hooks) 가능성도 열려있습니다.
    *   **실패 시나리오**: 악의적으로 조작된 심링크 기반 스킬을 다운로드했을 때, 에이전트 런타임 도구가 텍스트화된 심링크 파일을 무심코 파싱/복원하여 호스트 시스템의 중요 데이터(예: `/etc/passwd` 또는 사용자 `.ssh` 키)에 접근 및 유출.

**[ (b) P-2 불성립 결정의 파급 관점 ]**

*   **심각도(HIGH)** | docs/v1.6.8_shared_repo/working_history/preflight_20260720_001500.md : P-2 tool 매핑
    *   **근거**: 도구(Tool) 모델 상이로 인한 'IR tools 정규화 폐기 및 사람 적응(수동 포팅) 축소' 결정은 "이종 런타임 에이전트 교환"이라는 PRD 핵심 가치(S2)를 형해화(실질적 무의미)합니다. 설계서(AR10~12)의 충실도(Fidelity) 요구사항과 정면으로 배치되며, 사용자는 도구를 수동으로 재작성해야 하므로 "상호운용"이 아닌 "선언문 복사" 수준으로 전락합니다.
    *   **실패 시나리오**: 릴리스 후 사용자는 "클로드의 에이전트를 제미나이/코덱스에서 바로 쓸 수 있다"는 잘못된 기대를 품고(False Expectation) 임포트하지만, 모든 도구 실행이 마비됨. UX 신뢰도 추락 및 "기능 사기"라는 불만 폭주로 롤백 또는 긴급 재설계 압박 직면.

**[ (b2) 선검증 자체의 완결성 관점 ]**

*   **심각도(MED)** | docs/v1.6.8_shared_repo/working_history/preflight_20260720_001500.md : P-3 git/gh
    *   **근거**: `gh pr create`가 E2E 환경에서 실제 원격 저장소에 PR을 생성하는 것까지 실증되었는지 의문입니다. 단순히 로컬 환경에서의 keyring 재사용이나 dry-run 수준을 "실증됨"으로 표기했을 위험이 큽니다.
    *   **실패 시나리오**: 실제 공유 레포에 기여(Contribution) 워크플로우를 태울 때, 봇 계정의 권한(Token Scope) 부족, 브랜치 정책 충돌 등으로 실제 PR 생성이 원천 차단됨.

*   **심각도(MED)** | docs/v1.6.8_shared_repo/working_history/preflight_20260720_001500.md : P-5 IR 왕복
    *   **근거**: 단순히 클로드의 마크다운(md)을 IR로 변환하고 `extras`를 통해 원문을 보존하는 간이 테스트만 수행한 채 "왕복 실증 완료"로 단정지었습니다. codex의 복잡한 `.toml` 샌드박스 룰이나 제미나이의 고유 제약사항이 반영된 상태에서의 완벽한 실제 렌더링 및 양방향 무손실 변환은 검증되지 않았습니다.
    *   **실패 시나리오**: 타 런타임의 복잡한 스킬 메타데이터가 왕복(Export/Import) 과정을 거치며 데이터 유실(Data Loss)을 겪고, 원래의 런타임으로 복귀 시 파싱 에러를 유발하여 에이전트 파일이 영구 손상됨.
