## 3. 이 루프에서 실제로 배운 것

### 좁은 축만 파면 다른 축이 통째로 안 보인다
R2~R7 여섯 라운드가 전부 "역치환표가 기계적으로 실행 가능한가" 한 축이었다. 두 엔진이 그 축에서
수렴한 뒤 **렌즈를 넓히자 R8 에서 곧바로 새 결함**이 나왔다 — 요약줄이 4단계를 일괄
"전 생성 하네스 전파"라 규정하는데 같은 파일 다른 줄은 "전파 안 됨"이라 판정한 자기모순.
R13 에서 한 번 더 넓히자 **7건**(HIGH 2)이 나왔다. 수렴은 "결함이 없다"가 아니라
**"이 렌즈로는 더 안 보인다"** 였다.

### 수정이 수정을 부른다 — 과잉 명세
R13 이 고친 3곳이 R14 에서 전부 새 지적을 받았고, R14 가 고친 3곳이 R15 에서 또 받았다.
원인은 일관되게 **과잉 명세** — 완료 조건을 못박으려다 아직 정하지 않아야 할 설계까지 확정했다.
특히 R11 에서 "아직 안 한 설계를 단정하지 말라"는 지적을 받고도 **R13 에서 같은 실수를 반복**했다
(고아 검사 수단으로 "이 파일에서 export 금지"까지 확정). 계획서 자신의 R-1(추측 금지) 위반이다.

### 엔진이 갈릴 때는 투표가 아니라 근거로
- **R6·R15:** codex "새 결함 없음" · agy 결함 있음 → **agy 가 맞았다**(2회).
- **R11:** 양 엔진이 같은 문장을 지적했으나 이유가 정반대였다(codex "직접 수정 불가피하지 않다" ·
  agy "불가피하다"). **확정할 수 없는 것을 확정하지 않는 쪽**으로 정리해 양측을 모두 만족시켰다.
- **R15 codex 는 목표 달성 여부가 아니라 "판정 가능한가"만 보고 통과**시켰다. 통과 판정도 검증 대상이다.

### 리뷰어 자신이 만든 판정 오류
R2 에서 codex 가 `loop-self-eval.md` 를 `MANAGED_RELS` 에 추가하라고 권고했으나 **기각**했다 —
실측 결과 이 파일은 생성 하네스에 복사되지 않는 팩토리 내부 참조이고, 실제 생성본인
`external-review-loop.md` 에는 해당 오서술이 **0건**이라 이 오보는 전파된 적이 없다.
codex 도 R3 에서 기각이 타당하다고 확인했다.

## 4. 부수 발견 (이 단계 범위 밖 · 미해결)

1. **런처 SIGKILL 시 `status` 가 `running` 에 고착** — 실사용 3회 관측(R9·R14 등). 프로세스가
   전부 죽었는데 원장은 "실행 중"으로 남아 수동 정정이 필요했다. 터미널 상태를 쓰는 trap 이 없다.
2. **동시 실행이 agy 를 타임아웃시킨다** — agy 는 **단독 실행 시 239초**로 성공하는데
   런처의 `--print-timeout 300s` 상한 바로 아래다. codex 와 동시 실행하면 자원 경합으로 초과한다.
   R8·R9·R14 실패가 전부 이 원인이었고, **포그라운드 순차 실행으로 바꾸자 R15~R17 전부 성공**했다.
   프롬프트 크기 가설은 실측으로 기각됐다(짧은 프롬프트도 동시 실행 시 실패).
3. **`ok` 판정이 리뷰어 거부를 유효 리뷰로 센다** — `rc=0` + 비어있지 않은 출력이면 `ok` 라,
   리뷰어가 "못 하겠다"고 답해도 정상 리뷰로 집계된다.

셋 다 **팩토리 정본(`skills/myharness/`) 변경**이라 자체 게이트가 필요하다. 이 단계에서 고치지 않았다.
