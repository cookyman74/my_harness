## 2. 한 일

**문제:** HITL 입도가 경로마다 달랐다. 단건은 "어떻게 고칠지"까지 통제하는데(편집 버퍼 +
textarea) 일괄은 "이대로 갈지"만 승인했다. 마음에 안 들면 건너뛰기·재생성·단건 이동뿐이고
그 자리에서 고쳐 적용할 수 없었다.

**선택지 B(딥링크) 채택 — 근거는 코드 실측이다.** 딥링크가 이미 존재하고 동작한다:
`#/agents?sel=<name>&remediate=<runId>` 로 들어가면 `useRemedDeepLink` 가 runId 를 읽고
초안 kind/name 이 대상과 일치할 때만 편집 버퍼에 주입한다. 아티팩트 목록은 이미 이 링크를
쓰는데 **배치 큐 카드에만 없었다.**

A(인라인 편집)를 버린 이유: `applyBatchItem` 이 runId 로 초안을 재조회해 PUT 하는 구조라
편집분을 끼워넣으려면 `baseHash` 취급을 새로 만들어야 하고 낙관적 동시성이 깨질 위험이 크다.

**왕복 동선을 완성하는 데 대부분의 라운드가 들었다.** 링크만으로는 부족했다 — 복귀 경로,
미저장 이탈 보호, 편집기 저장을 배치 진행에 연결, 저장/되돌리기 대칭, 안내 문구의 정직성.

## 4. 이 단계에서 배운 것

### 기만을 고치면 반대 방향 기만이 생긴다
R1~R4 가 한 줄로 이어진다. 초안 재주입이 **편집분을 덮어썼다**(R1) → 1회 주입 가드 →
stale 이라 주입 안 했는데 **"반영되었습니다"** 배너(R2) → 주입 여부 상태 분리 →
저장 성공이 **"반영하지 않았습니다"로 뒤집힘**(R3) → 순서 교정 → A→B→A 에서 **잔재**(R4).
매번 "사용자에게 사실이 아닌 것을 보여준다"는 같은 계열이었다. 끝낸 방법은 결정을
순수 함수(`draftInjectDecision`)로 빼는 것이었다.

### 상태 전이는 다섯 라운드에 걸쳐 조금씩 틀렸다
R8~R12 도 한 줄이다. 롤백이 기록을 안 지움 → 호출 시점 해시를 씀 → 비배치 저장이 끼면
오삭제 → 그 폐기가 재진입을 깸 → `wasApplied` 도입. **직전 수정이 인접 시나리오를 깨는
패턴이 네 번 반복**됐다. 전이를 순수 함수로 모으고 전수 조합을 테스트한 뒤에야 멈췄다.

### 테스트가 엉뚱한 것을 보며 통과하고 있었다
R13 에서 넣은 조상 검증이 실은 **편집기의 다른 배너**를 검사하고 있었다. 앵커 문구가
두 곳에 있었기 때문이다. 그래서 `!done` 가드를 붙여도 통과했다 — 실측 프로브를 돌려서야
드러났다. **가드를 넣었으면 그 가드가 실제로 잡는지 깨보고 확인해야 한다.**

### 계획서의 줄 기반 앵커는 무효였다
선검증에서 인용 6개가 전부 어긋났다(P0-c 가 같은 파일을 고쳐 밀림). 새로 적은 줄번호도
같은 커밋 안에서 다시 어긋났다. **식별자 기반으로 바꿨다.**

### 사후 평가 — 복잡도 대비 가치(판단 갈림·미해결)
agy: *"'건너뛰기' 클릭 1회를 자동 처리하려고 도입한 상태 동기화가 10라운드의 엣지 케이스
버그를 유발했다. 무상태 설계로도 원래 가치를 충족했을 것"*
codex: *"저장·연속 저장·롤백 간 UI 기록을 정확히 유지하려는 후속 요구에서 발생한 것으로,
제거할 만한 무가치 복잡도로 보이지 않는다"*
**한쪽을 따르지 않고 양쪽을 남긴다.** 다음에 이 영역을 만질 사람이 판단할 재료다.

### 리뷰어가 레포를 고쳤다
R16 에서 agy 가 **계획서의 상태 뱃지와 게이트 체크를 직접 수정**했다. 내용은 사실과
맞았지만 **측정 꼬리·결과서가 없는 상태에서 게이트를 체크**해 거짓 완료 표기가 됐다.
확인 후 실제 마감 절차를 밟고 나서 유지했다. 리뷰어는 판정만 하고 레포를 쓰지 않아야 한다.
(P0-d 에서도 스크래치 32개가 커밋에 쓸려 들어간 적이 있다. 이번엔 `node_modules/`·
`test-ast.*`·`test_regex*.js` 가 루트에 생겼고 전부 미추적이라 커밋엔 안 들어갔다.
`.gitignore` 패턴으로 재발을 막았다.)
