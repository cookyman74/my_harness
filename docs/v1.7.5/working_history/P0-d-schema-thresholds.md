## 2. 한 일

### 계층B 확장 지점
`evaluation_mode` 를 `"static"|"deep"|"cross_checked"` 유니온으로 열고, 산출 지점을
`evaluateArtifacts` 안 `MODE` 단일 선언으로 모았다. `confidence` 하드코딩 3곳
(`:250` 0.45 · `:261` 0.5 · `:278` 0.5 — **계획 초안은 2곳으로 적었고 `:278` 이 누락돼 있었다**)을
`CONFIDENCE_BY_RUBRIC_MODE` 표 + `confidenceOf()` 로 단일 출처화했다. 값은 현행 유지.

`deep`/`cross_checked` 는 **의도적으로 미정의**로 뒀다. 추측값을 넣으면 계층B가 붙기도 전에
"높은 confidence" 가 UI 에 노출된다. 호출 시 throw 하는 fail-fast 구조이고, 현재 런타임은
`MODE = "static"` 고정이라 도달하지 않는다(양 엔진 확인).

### 임계 캘리브레이션 — "확정" 을 철회했다
픽스처를 신설했다(`test/fixtures/quality/{good,bad}`). 기존 `fixtures/definitions/{accept,reject}`
는 **파싱 가능성** 판정용이라 등급에 못 쓴다(R-1 에 따라 "없다"를 먼저 확인하고 만들었다).

처음엔 "현행값 유지 **확정**"이라 적었으나 양 엔진이 과잉 주장이라 지적해 철회했다.
codex 의 근거가 결정적이었다 — **`bad` 픽스처는 본문이 짧아 구조 min-gate 에 먼저 걸려
`gradeOf` 가 임계와 무관하게 D 를 반환한다.** 즉 A/B/C 임계를 전혀 검증하지 않는다.
`good` 의 "B 이상"도 A 임계나 B/C 경계를 구별하지 못한다.

→ **"기준선 잠정 유지(표본 부족)"** 로 정정. 오분류가 없으니 지금 바꿀 근거도 없다는 것까지가
정확한 서술이다. 확정 조건(min-gate 미발동 상태의 A/B/C/D 독립 픽스처 다수)은 이월했다.

### 고아 가드 — 정규식 3라운드 실패 후 AST 로
계획서 요구는 "대상을 열거하지 않는 프로젝트 범위 검사"였다. 정규식으로 시작해 **3라운드
연속 결함**이 나왔다:

| R | 결함 | 방향 |
|---|---|---|
| R1 | 블록 주석 제거가 문자열 속 `/*` 로 파일 절반을 삼킴 | 오탐 |
| R2 | import 제거 정규식이 부수효과 import 뒤 코드까지 폭주 | 오탐(시한폭탄) |
| R2 | 인라인 `// 주석` 미제거 → 이름이 참조로 위장 | 누락 |
| R2 | `React.FC` 타입주석·`memo()`·`forwardRef()` 형태 미수집 | 누락 |

전부 "소스를 정규식으로 읽는다"에서 나왔고 양 엔진이 AST 를 권고했다. `typescript` 5.9.3 이
이미 devDependency 라 전면 교체했다. 그 뒤 R3 에서 AST 순회 자체의 결함 3건(참조 유실·중첩
선언 누락·`export default` 자가참조 위장)을, R4·R5 에서 default export 판정 정밀도 3건을
더 잡았다. 최종적으로 8형태를 실측 검증했다(탐지 6 / 오탐금지 2).

**즉시 효과:** 미사용 import 를 지우자 `MetricCell` 이 진짜 고아가 되어 가드가 바로 잡았다.

### `noUnusedLocals` — 계획 가정이 실측과 달랐다
계획서는 위반 46건을 균질한 죽은 코드로 가정했으나 실제로는 갈렸다:

- **33건 = 안 쓰는 import** → 제거(의미 변화 없음)
- **13건 = 미배선 지역 선언** → `screens.tsx` UI 11 + 테스트 지역변수 2

11개 중 `RunDetail` 은 **전용 회귀 테스트(`webrundetail.test.ts`)가 있는데 화면에 연결돼
있지 않고**, `HarnessScorecardCard` 는 P0-c 배선 대상이다. 이 레포 교리상 삭제는 고위험·사람
승인 사항이라(제안서 AE5 `delete-candidate`) 가드가 임의로 지우게 하지 않았다.
**사용자 결정 = 동결 유지.** 부채를 명시 목록으로 고정하고, 목록이 실제 소스와 어긋나면
실패하는 테스트를 뒀다(목록이 낡아 부채가 안 보이게 되는 것을 차단).

## 4. 이 라운드에서 배운 것

### 도구 선택이 곧 결함률이다
정규식으로 소스를 읽는 동안 R1~R2 에서 4건이 나왔고, 전부 같은 뿌리였다. 파서로 바꾸자
그 결함군이 통째로 사라졌다. 지적을 하나씩 땜질하는 대신 **지적들이 공유하는 뿌리**를
봤어야 했다 — 두 엔진이 먼저 그걸 지적했다.

### 가드를 만들면서 가드가 막으려던 실수를 했다
동적 import 오탐을 막는 조건부 가드를 **정규식으로 짰다**(R4 codex). 같은 파일 안에 AST
파서를 두고도. 정규식→AST 전환을 한 그 커밋에서 벌어진 일이다.

### 리뷰어가 레포에 남긴 파일을 커밋했다
`git add -A harness-ui` 가 스크래치 32개를 쓸어담았다(R7 codex). 출처는 외부 리뷰어다 —
codex·agy 가 `--add-dir` 로 임시 검증 파일을 만든다. **이 세션에서 같은 실수를 반복했다**
(앞서 `git add -A skills docs` 로 감사 파일 27개를 쓸어담은 적이 있다).
`.gitignore` 패턴으로 재발을 막았다.
