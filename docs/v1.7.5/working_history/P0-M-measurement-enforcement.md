# P0-M — 측정 강제 설계 · 결과서

작업일: 2026-08-31 ~ 09-01 · 브랜치: `feat/eval-upgrade-v175` · 등급: **중대**
산출물: `docs/v1.7.5/design/P0-M-measurement-enforcement.md` (설계서 · **구현 아님**)
외부 리뷰: **R1~R32** · codex(`gpt-5.4-mini` high) + agy · 러너 claude 제외 · **R31 codex·R32 agy 2연속 HIGH 0 → `converged`** (측정 꼬리 `align 1.0`·`regr 6.4`·confirmed 37)

> ⚠ **§1-8 해소 판정은 여기서 하지 않는다.** 이 단계의 산출물은 설계서이고 구현은 별도 착수다.

## 1. 무엇을 설계했나

정본이 "측정 = 자동"이라 보증하는데(`loop-self-eval.md`) 그 자동을 수행하는 기계가 없다.
실패가 두 번 실증됐다(22라운드 후 scorecard 0건 / 12라운드 수동 실행).
원 제안서는 **6라운드 외부리뷰에서 메커니즘 안이 매번 무너진 뒤** 해법을 이 과제로 이관하고
**문제·수용 기준·제약 12건**만 남겼다.

**선검증에서 "없다"를 먼저 확정했다**(6건): holdout 실행 경로 0건 · attestation 영속 경로 부재 ·
stage risk 권위 부재 · hook 의 project/tier 는 baked 리터럴 · 리스크↔티어 독립축 · 궤적 수집 부재.
**이 부재들이 6라운드가 무너진 이유다** — 기반 계약이 없는데 그 위에 안전조건을 쌓았다.
그래서 이 설계는 **기반 계약을 먼저** 만든다:

| | 계약 | 요지 |
|---|---|---|
| ① | **영속 증거** | `docs/{project}/_eval/attestations/*.json` — 커밋되는 경로. 휘발 경로에 두면 삭제가 곧 무력화다 |
| ② | **stage risk 권위** | 계획서 단계 헤더의 `**등급:**`. `risk_source` 에 경로+블록 sha256. 표기 없으면 `critical`(fail-closed). `manifest` 어휘 미사용 |
| ③ | **루프 identity** | `{stage_id}@{opened_at}@{nonce}` 승계 + `run_id` 라운드별 갱신. `O_EXCL`(단 같은 루프 재발급은 허용) |

**강제 장치는 호출자 외부(`pre-commit`)이고 트리거는 두 축이다:**
- **측정 의무** — 결과서에 `termination_reason` 이 적히면(= 루프가 끝났다는 주장) attestation **존재**를 요구. terminal 종류는 묻지 않는다.
- **완료 주장** — 게이트 체크박스 `[ ]`→`[x]` 전환 시 attestation + `loop_instance_id` 대조 + terminal 정상.

## 2. 이 단계가 배운 것 — 왕복 열 라운드

**R4~R15 가 같은 축을 오갔다.** 구멍을 막으면 교착이 생기고, 교착을 풀면 다른 구멍이 열렸다.

| R | 무엇을 했나 | 무엇이 깨졌나 |
|---|---|---|
| R4 | 실패 terminal 을 차단 대상에 넣음 | — |
| R5 | 오타 수정 교착 해소 | 신규 경로가 느슨해짐 |
| R6 | 신규 경로 엄격화 | **실패 기록 커밋이 막힘**(제약 ⑧ 재발명) |
| R7 | 트리거를 체크박스 하나로 단일화 | **실패 라운드 측정이 유실됨** |
| R10 | 완료 후 증거 변경도 재검사 | **휘발 산출물이 없어 영구 교착** |
| R11 | 측정 의무를 결과서로 분리 | — |
| R13 | 완료 후 수정 면제 복원 | — |
| R14 | 트리거를 `termination_reason` 으로 좁힘 | **루프 중간 커밋 차단**을 그 전까지 못 봄 |

**원인은 하나였다: 완료 주장과 측정 의무를 하나의 트리거로 묶으려 한 것.**
전환은 순간이고 주장은 지속되며, 측정 의무는 그 둘과 또 다른 시점에 생긴다.
세 축을 하나로 누를 때마다 어딘가가 찢어졌다. **분리하고 나서야 멈췄다.**

두 번째 교훈: **막을 수 없는 것을 막으려 하면 교착이 난다.** 휘발 산출물은 되살릴 수 없고
커밋 밖 앵커는 없다. 그래서 §9-1 위협 모델에 **막는 것과 막지 못하는 것을 표로 갈라 적었다** —
망각·건너뜀·실패를 완료로 적기는 막고, **의도적 위조와 완료 후 증거 변경은 못 막는다**.
실제 실패 2회는 **둘 다 망각**이었지 위조가 아니었다.

## 2-1. R18~R32 — 세 갈래로 갈린 교훈

**① "X 만 요구" 형태의 조건이 세 번 뚫렸다.**
원장 **존재**(R3) → id **존재**(R19·R26) → attestation **존재**(R27).
**존재는 내용을 보장하지 않는다.** 요구를 적을 때마다 *"그것이 비어 있거나 남의 것이면?"* 을
함께 물어야 했다. R27 의 빈 스텁, R26 의 타 단계 도용이 정확히 그 빈틈이었다.

**② 정본을 인용할 때는 그 파일을 열어야 한다 — 세 번 지적받았다.**
- R14: Step 5~7 이 **루프 안**에서 반복된다(설계서는 루프 밖으로 전제 → 중간 커밋 전부 차단)
- R22: 루프 종료 후엔 **Step 8 만** 있고 커밋 단계가 없다(Step 7.5 신설은 배선 불가)
- R24: **Step 8 이 `BLOCK` 검사보다 앞**이라 차단 상태에서도 attestation 이 발행된다
  (내가 R18 에서 반대로 적어 우회 구멍을 남겼다)

세 번 다 **정본 의사코드의 순서**가 쟁점이었다. 요약을 읽고 구조를 지어내면 배선 단계에서
구현할 수 없다.

**③ 막을 수 없는 것과 이미 막힌 것을 구분해야 한다.**
- 못 막는 것: 의도적 위조 · 완료 후 증거 변경(휘발 산출물 복원 불가) → **위협 모델에 명시**
- 이미 막힌 것: `degraded-blocked` 의 진행 금지(정본 소관) → **재정의하지 않는다**
- 막아야 할 것: 망각 · 건너뜀 · 실패를 완료로 적기 · 타 단계 도용 · 빈 스텁
"막는다"고 적을 때마다 **그 수단이 실제로 있는지** 확인했다(R19 는 그 반대 사례 — 대조할 id 가
커밋 안에 없는데 막는다고 적었다).

## 3. 같은 문서 안의 "정본 1 + 사본 N"

규칙이 §1·§4·§5·§7·§8·§9-1·수용 기준·계획서에 흩어져 있어 **한 곳을 고치면 나머지가 반대로
말하는 일이 다섯 번**(R8·R13·R15·R21·R23) 났다. B0 에서 배운 것이 한 문서 **안에서** 반복됐고,
R21 부터는 **설계서 ↔ 계획서** 사이로도 번졌다.

매번 다른 조합이라 "한 번 훑었으니 됐다"가 통하지 않았다 — R15·R21·R23 이후 **전파 자체를
정규식으로 스캔**했고(정책 문구·상태값·트리거 문구·개념 8종), 그때마다 놓친 곳이 나왔다.

R15 뒤 **전파 자체를 기계적으로 점검**했다(해시 차단 잔존 · `eval_status` 값 집합 · 옛 트리거
문구 · "트리거는 하나" 잔존) → §5 본문 한 곳을 더 찾아 고쳤다.

## 4. 리뷰가 바꾼 결정

| 라운드 | 원안 | 바뀐 것 |
|---|---|---|
| R1 | 트리거 = `_workspace/reviews/` 흔적 | **제약 ⑦의 재발명**(gitignore 라 지우면 통과) → 커밋 diff 로 이동 |
| R2 | 성공 기준 = `eval_status == "ok"` | **생산자가 그 필드를 안 낸다**(실측) → 생산자·소비자 계약을 구현 범위에 포함 |
| R3 | `issues` 비지 않음을 무결성 조건에 | **결함 0건 수렴이 막힌다** → 판정은 `termination_reason` 이 한다 |
| R4 | 모든 증거가 커밋 안 | 위조를 못 막는다 → **위협 모델로 한계 명시**(막는다고 적지 않는다) |
| R15 | `eval-failed` 가 리뷰 실패+생성 실패 | 둘을 구분 못 해 파손을 통과시킨다 → **`eval-error` 분리** |

## 다음 단계 참조

- **이 설계서는 구현이 아니다.** 수렴했다고 §1-8 이 해소된 것이 아니다.
- 구현 착수 시 **세 축 분리**를 먼저 확인하라: 완료 주장(체크박스) · 측정 의무(`termination_reason`) ·
  증거 무결성(사후 감사). 하나로 합치려 하면 이 문서의 왕복이 반복된다.
- `pre-commit` hook 은 **staged diff** 만 본다 — 휘발 경로를 트리거로 쓰면 제약 ⑦이 되살아난다.
- 기존 하네스는 등급 표기가 없어도 **커밋이 막히지 않는다**(risk 는 게이트 강도이지 hook 조건이 아니다).
  등급 명시는 권고이지 강제가 아니다.
