## 공통 규칙 (모든 단계에 적용 · req)

### R-1. 추측 금지 — 소스코드 기반 결정
- [ ] 모든 작업 결정은 **실제 소스·실행 결과**로 근거를 댄다. "그럴 것이다"로 진행 금지.
- [ ] 파일·심볼·필드·경로를 인용할 때 **`file:line` 을 실제로 열어 확인**한다. grep 히트만으로 단정 금지.
- [ ] **워크플로우 파일에 키워드가 없다 ≠ 그 일이 안 일어난다.** 무엇을 *실행*하는지 본다(R1 에서 "eval CI 0건" 사실오류를 낸 원인).
- [ ] 존재하지 않는 인프라·필드·계약을 전제하지 않는다. 없으면 **"없다"를 먼저 기록**하고 신설을 별도 과제로 뺀다(제안서 §3-0 제약 ①④⑩).
- [ ] 착수 전 각 단계의 **P0 선검증**을 통과한다. 미통과 시 설계로 되돌아간다.

### R-2. 단계 완료 게이트 — 외부리뷰 2회 이상·중급위험 0
- [ ] 각 단계는 **`external-review-loop`(codex+agy·러너 claude 제외)를 최소 2라운드** 돌린다.
- [ ] 완료 조건 = **HIGH 0 이고 MEDIUM 0** 인 라운드가 **2회 연속**(중급위험까지 제거). LOW 는 판정 후 이월 가능.
- [ ] **축소(degraded) 라운드는 연속 카운트에 넣지 않는다.** 리뷰어 1종·PATH 밖 설치·런타임 실패 시 `degraded` 가 기록되며(`run-review.sh`), 그 라운드는 교차검증이 아니다. 복구 후 재실행한다.
- [ ] 복구된 리뷰어에게는 **`round==1` 과 동일하게 산출물 전체**를 준다(증분 diff 금지 — 그 리뷰어 관점의 미검토 구간이 남는다).
- [ ] 지적은 **전건 실코드 대조 후 판정**(확인/부분/이월/기각)하고 `verdicts.json` 원장에 **영문 enum**(`confirmed|partial|deferred|rejected|duplicate`)으로 기록한다. round>1 의 회귀 발견은 `source:"re-review"`.
- [ ] 루프 종료 시 **측정 꼬리 발행**: `bash skills/myharness/scripts/emit-loop-scorecard.sh _workspace/reviews/{stage}_verdicts.json`. 산출물의 `eval_status` 를 확인한 뒤에만 성공으로 기록한다.
- [ ] 결과서를 `docs/v1.7.5/working_history/` 에 남기고 `## 다음 단계 참조` 블록을 포함한다(`check-artifacts.sh` 통과).

### R-3. 체크리스트 운용 — 실시간 상태

## P0-e — 일괄 반영 경로의 편집 통제 복원 `⬜ 미착수`

**목표:** 일괄(batch) 반영에서 사용자가 **AI 초안을 고칠 수 없는** 비대칭을 해소한다.
**등급:** 표준(`harness-ui` 한정·정본 전파 없음) · **근거:** 코드 실측(아래)

> **문제 — HITL 입도가 경로마다 다르다.** 자동 적용은 어느 경로에도 없다(`remediate.ts:3` "AI=초안만·사람 diff 승인=유일 적용" · `evals.ts:358` `autoApply:false`). 그러나 **단건은 "어떻게 고칠지"까지 사용자가 통제**하고, **일괄은 "이대로 갈지"만 승인**한다.

| | 단건(E5-a) | 일괄(M-y3) |
|---|---|---|
| 초안 주입 위치 | **편집기 버퍼** `edited`(`screens.tsx:623`) | 항목 카드(읽기) |
| 초안 편집 | **가능** — `<textarea value={edited} onChange={setEdited}>`(`:785`) | **불가** |
| 검토 | diff + 저장(`:727` "저장하면 적용됩니다") | 항목별 diff 펼침(`:2598`) |
| 적용 | 저장(사람) | 항목별 `적용(저장)`(`:2604`) 또는 **`준비된 N개 모두 적용`**(`:2540` → `bulkApply(readyToApply)`) |

일괄 경로에서 사용자가 초안이 마음에 안 들면 선택지는 **건너뛰기 / 재생성 / 단건 화면으로 이동** 뿐이고, **그 자리에서 고쳐 적용할 수 없다.**

### P0 선검증 (착수 前 필수)
- [ ] 위 표의 6개 인용(`623`·`785`·`727`·`2540`·`2598`·`2604`)을 **직접 열어 재확인**
- [ ] `bulkApplyItems`(`:2474`)·`applyBatchItem`·공용 적용 함수(`:2461` "단건 카드·일괄 적용 공용")의 입력 계약 확인 — 편집된 content 를 받을 수 있는 형태인지, `baseHash` 낙관적 동시성(`:2578-2582` stale 처리)과 어떻게 맞물리는지

- [ ] 편집 허용 시 `baseHash` 가 무엇을 기준으로 계산돼야 하는지 확정(원본 기준 유지 vs 편집본) — **틀리면 낙관적 동시성이 무력화**된다
