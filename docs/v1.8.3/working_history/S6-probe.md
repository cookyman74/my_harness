## 2. A절 — 가드 테스트 먼저 (T-PB1)

`tests/test-probe-guard.sh` 신규. **모델을 호출하지 않는다** — ①②는 가드가 막는 경로, ③은 PATH 앞 스텁만 부른다(실모델 0 · 비용 0). 그래서 CI 에 넣어도 안전하다.

**구현 전 적색:** ①(rc=127≠2)·③ 실패. ②와 ①의 "파일 0개" 는 스크립트가 없어 **자동으로** 참이라, **③이 그 둘을 공허하지 않게 만드는 대조군**이다(계획서가 지적한 모양 그대로).

**변이 검증 3종 — 전건 적발:**

| 변이 | 적발 |
|---|---|
| 가드 제거(`if false`) | ①②③ **동시 실패**(rc=0 · 파일 생성 · 도구 호출) |
| 가드 **전에** 파일 생성 | ① 적발("실행 루트에 파일이 생겼다") |
| 옵트인 뒤 즉시 종료(스크립트 무력화) | ③ 적발("옵트인했는데도 스텁이 한 번도 호출되지 않았다") |

**작성 중 내 실수 하나:** 처음엔 테스트 PATH 에 node 를 넣지 않아 스크립트가 **정당하게** rc=2 로 멈췄고 ③이 그 이유로 실패했다 — 가드 결함과 구분되지 않는 **가짜 적색**이었다. node 심을 넣어 고쳤고 그 이유를 테스트 주석에 남겼다.

## 4. C절 — 실측 결과 (비용 승인 후)

### 확정된 것

| probe | 결과 |
|---|---|
| **P1** | **alias 3종 전부 생존** — `opus`→`claude-opus-5-5` · `sonnet`→`claude-sonnet-5` · `haiku`→`claude-haiku-4-5-20251001`. **죽은 alias 없음 → 데이터 변경 없음** |
| **P2** | **폴백이 실제로 받는다.** 대조 3종이 갈랐다: ① 없는 alias·폴백 인자 **없음** → `modelUsage` **비어 있음**(모델이 안 돌았다) ② 없는 alias + `--fallback-model haiku`(**기본과 다른 군**) → **haiku** ③ 기본 세션 → `opus[1m]`. **①②가 갈리므로 "기본값으로 떨어진 것" 이 아니다** |
| **P4** | **`effort` 는 `usage` 에 필드로 없지만 적용은 관측된다** — 스트림의 `effort` 문자열은 **슬래시 명령 이름**뿐이고, CLI 에 **`--effort <level>`** 이 있다. 같은 프롬프트에서 `--effort low` → `thinkingTokens` **0**, `--effort high` → **112**. **관측 채널 = `modelUsage.*.thinkingTokens`** |
| **P5 (google)** | 금지값 `MINIMAL` **거부 재현** — `rc=1` · `invalid model selection … is not recognized` · **대조군 `HIGH` 는 rc=0** |

### 확정되지 않은 것 — **미실측으로 남긴다**

| probe | 왜 |
|---|---|
| **P3** | **호출 `model` 은 적용된다(확정)** — 정의가 `opus` 인데 호출 `model:"haiku"` 로 haiku 가 돌았다. **그러나 정의값이 spawn 에 반영되는지는 확정 못 했다:** 호출을 생략하면 `opus[1m]` 이 나오는데 **세션 기본도 `opus[1m]`** 이라 「정의가 이겼다」와 「기본값」을 못 가른다. 정의를 `haiku` 로 **바꾼 뒤** 호출 생략으로 재보니 **여전히 `opus[1m]`**(바꾼 값이 아니다) → 캐시인지 미반영인지 구분 불가 |
| **P2c** | **측정 경로 둘 다 막혔다** — 새 정의 파일은 세션 등록 목록 밖이라 spawn 불가(`Agent type … not found` · 실측) · 기존 정의의 `model:` 을 바꿔도 반영되지 않는다(위) → 폴백인지 캐시인지 구분 불가 |
| **P2b** | 실행은 됐으나 **403 자체는 여전히 미실측** — 이건 대리 관측이다(설계서 §8-3 원문 유지) |
| **P5 (openai)** | `none` 을 **codex CLI 가 거부하지 않았다**(rc=0 · 허용값 `low` 와 같은 응답). **CLI 는 API 가 아니다** — CLI 가 값을 정규화·무시할 수 있으므로 이것은 **400 의 반증이 아니다**. `effort_forbidden` **변경 없음** |
| **P5 한계(기록)** | **스크립트는 「금지값 거부」와 「도구 오류」를 가를 수 없다**(둘 다 출력 + rc≠0 · S6 R18 codex). 프로바이더별 거부 문구를 스크립트에 적으면 **그게 또 하나의 정본**이 된다 → 판정을 지어내지 않고 `rc≠0: 거부 또는 도구 오류 — 스크립트는 못 가른다` 로 적어 **사람이 원문으로 판정**하게 한다(설계서 §8-3 의 원래 지시와 같다). 이번 실측의 google `MINIMAL` 은 원문이 `invalid model selection … not recognized` 라 **거부로 판정**했다 |

**→ `pinned_id` 는 계속 비운다.** §7-3 의 결론 조건(정의가 지배한다)이 충족되지 않았다. **후속 측정은 정의를 바꿔 커밋한 뒤 새 세션에서 1턴**이다.

### 프로파일을 바꾸지 않은 이유

- 죽은 alias 가 **없다** → 교체할 것이 없다.
- **`confirmed_at` 은 갱신하지 않았다.** 참조 문서가 그 필드를 "사람이 **공식 문서를 눈으로 확인한 날**" 로 정의한다 — probe 는 **런타임 관측**이라 그 필드를 갱신하면 의미가 뒤틀린다. **계획서 P1 의 「갱신: … `confirmed_at`」 지시가 필드 정의와 충돌**하며, 설계서 §8-3 에 그 정정을 적었다.
- 따라서 **데이터 변경 0** → 이 단계에는 「중대 승격」 사유가 없다(정본 문구 변경도 설계서·결과서에 한정).
