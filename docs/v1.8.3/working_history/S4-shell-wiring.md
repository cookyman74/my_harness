## 3. 설계서 결함 2건 — 둘 다 실행이 잡았다

### 3-1. 구간 B 스니펫이 override 를 조용히 삼켰다 (T-E3 가 성립하지 않았다)

설계서 스니펫의 첫 분기가 이랬다:

```sh
if [ "$EG_REV" = none ]; then
  REVIEWERS=""                       # override 여부를 보지 않는다
  DEG="…반출 허용 리뷰어 0"
else
  … override 토큰이 허용 밖이면 die_launcher …
fi
```

`EG_REV = none` 은 **모든 토큰이 허용 밖**이라는 뜻인데, 그 경우를 특례로 먼저 삼켜 버리므로 `runtime-only` + `REVIEWERS_OVERRIDE=agy` 가 **`no-reviewers` 로 조용히 사라진다**. **같은 설계서의 판정표가 요구하는 `die_launcher "egress 위반: <tool>"` 이 성립하지 않는다.**

→ **특례를 없애고 루프가 균일하게 처리**하게 했다(`none` 에는 어떤 토큰도 매치되지 않으므로 전부 `*` 분기로 간다). 팩토리 실측으로 확인:

```
# 프로파일 ⑥ 을 runtime-only 로 바꾸고
REVIEWERS_OVERRIDE=codex … run-review.sh
ERROR: egress 위반: codex        →  status: failed
```

### 3-2. 계약 줄 어휘가 데이터 파일 어휘로 샜다

데이터 파일은 `review_tiers.*.codex = "runtime-default"`("env 를 설정하지 않는다")를 쓰는데 `egress` 가 그것을 **그대로 계약 줄에 실었다**. 셸은 `none` 만 특례로 보므로 결과적으로 **`codex exec -m runtime-default`** 라는 없는 모델명이 리뷰어에게 넘어갔다.

설계서 §3-5 는 계약 줄 어휘를 **"모델 ID 또는 `none`"** 으로 정해 뒀다 — 즉 `runtime-default` 는 애초에 그 줄에 나오면 안 되는 값이고, **해석기가 번역**해야 한다. 셸이 데이터 파일 어휘까지 알면 아는 곳이 둘이 된다. `cmdEgress` 에서 번역하도록 고쳤고 §2-2 도 정정했다. 이제 출력이 설계서 §3-5 예시와 정확히 같다(`REVIEW_MODEL_CODEX: none`).

## 3-3. 배선이 드러낸 데이터 결함 — 실재하지 않는 리뷰어 모델명

R1 에서 agy 가 **런타임 실패**했다. 원인은 배선이 아니라 데이터였다:

```
error: invalid model selection (--model "Gemini 3.5 Flash (High)") — not recognized as a known model
Available models: Gemini 3.8 Flash (High/Medium/Low) · 3.7 Flash · 3.6 Flash · Gemini 3.1 Pro (High/Low) · …
```

Flash 는 **3.8·3.7·3.6** 뿐이고 **3.5 는 없다**(`Gemini 3.1 Pro (High)` 는 실재 — `critical` 값은 옳았다).

**그 이름은 정본 `run-review.sh:57` 주석에서 왔다.** S0 이 데이터 파일을 만들 때 그 주석을 충실히 옮겼고, **그 전까지는 `AGY_MODEL` 을 프로파일에서 받지 않아 아무도 이 이름을 쓰지 않았다** — 주석 안에서 조용히 낡은 것이다. S4 가 값을 **실제로 CLI 인자로 넘기기 시작한 순간** 드러났다.

→ `review_tiers.light/standard.agy` 를 **`Gemini 3.8 Flash (High)`** 로 고치고, 정본 주석에서 낡은 이름을 지웠으며(그 주석은 이제 "프로파일이 소유한다" 고만 말한다), 설계서 §2-2 를 정정했다. **고친 뒤 agy 를 다시 돌려 정상 통과를 확인했다.**

> **배선은 제 일을 했다.** 틀린 값을 조용히 넘기지 않고 **fail-closed 로 멈췄다**(`status: failed` · `degraded` 에 런타임 실패 기록). 이 값은 **이 설치에서 관측한 것**이라 오프라인 테스트로 고정할 수 없다 — MA8 의 `confirmed_at` 부패 기구가 다루는 종류이고 §8-3 probe 후보다.

## 5. `python3` 의존을 없앴다 — 측정하지 않고 제거

계획서는 windows 러너의 `python3` 가용성을 CI 로 **측정**하라고 했다. 측정 대신 **의존을 없앴다**(12곳을 `node -e` 헬퍼 하나로). 근거: node 는 이 스위트의 **하드 의존**이고(CI 가 `setup-node` 로 깐다) `python3` 는 windows 러너에서 보장되지 않는다. **S1·S3 에서 macOS 에서 안 보이던 것이 windows 에서만 깨진 선례가 둘** 있다 — 한 번 측정해 "있더라" 를 확인하는 것보다 의존 자체를 지우는 쪽이 낫다. 정본 영향 **0**(테스트 쪽 변경).

### 7-1. 내가 만든 공허한 테스트 — agy 가 잡았다

새 블록(AG·AH)을 `e9 15` 와 T-E9 의 `ok` 줄 **사이**에 끼웠다. 두 블록이 각각 `b=""` 로 시작하므로 **T-E9 15케이스가 쌓은 실패가 지워지고**, 그 `ok` 줄은 엉뚱한 블록의 `b` 를 읽고 있었다 — **T-E9 가 통째로 공허해졌다**. 단정을 `e9 15` 직후로 되돌리고 라벨 충돌도 정리했다. **역검증:** 중복 토큰 가드를 지우면 T-E9 가 `⑨14`·`⑨15` 로 정확히 실패한다(그 전에는 조용히 통과했다).

> 이 레포가 가장 경계하는 계열(공허한 단정)을 **내가** 만들었고 리뷰어가 잡았다. 테스트를 **끼워 넣을 때 기존 단정의 누적 변수를 밟지 않는지** 보는 것이 규칙이다.

## 9. 2-OS 게이트가 세 번째로 결함을 잡았다 — 이번엔 **테스트가 windows 에서 처음 돌았다**

S4 는 `run-review launcher contract` 스텝을 **신설**했다. 즉 이 스위트 46건이 windows 에서 도는 것은 이번이 처음이고,
첫 push(`740e2b6`)에서 **linux green · windows 6건 실패**가 나왔다. 셋으로 갈렸다.

### 9-1. 런처의 실제 결함 — 락이 windows 에서 무력했다 (C·G·O·V 4건 · 원인 하나)

`pid_alive(){ ps -p "$1" -o pid= >/dev/null 2>&1; }` — Git Bash(MSYS)의 `ps` 는 이 조합에 **rc≠0** 을 준다.
그래서 **모든 락이 "죽은 락"으로 판정**돼 회수됐다: 살아있는 락을 뚫고 실행하고(C), 타 사용자 PID 를 죽은 것으로 보고(G),
**점유 중인 다른 실행의 상태 파일을 덮었다**(O·V — R22·R31 이 HIGH 로 막아 둔 바로 그 행동이 한 OS 에서 되살아나 있었다).

고친 방식이 중요하다 — **자기 PID 로 능력을 실측한다**. 자기 PID 는 반드시 살아 있으므로 거기서 rc≠0 이 나오면
"그 PID 가 죽었다" 가 아니라 **"이 조합을 쓸 수 없다"** 는 관측이다(OS 이름을 묻지 않는다).
못 쓰면 `kill -0`, 그래도 아니면 `ps` 목록에서 PID 를 찾는다(EPERM 보정). POSIX 경로는 코드도 결과도 불변(macOS 46/46 · 건너뜀 0).

### 9-2. 전제가 그 OS 에 없는 것 — **건너뛰되 통과로 세지 않는다** (2건)

- `G st-i` 는 "타 사용자의 **살아있는** PID(pid 1)" 를 전제로 EPERM 오판을 본다. Git Bash 에는 그런 PID 가 없다.
- `N` 은 "`chmod 555` 가 쓰기를 **막는다**" 를 전제로 상태 기록 실패를 본다. NTFS/Git Bash 는 막지 못한다.

둘 다 **전제를 실측**해(임시 디렉토리에 실제로 써 본다) 없으면 `⏭ SKIP` 줄을 찍고 **건너뜀 카운터**로 센다.
합계 줄이 `통과 44 · 실패 0 · 건너뜀 2` 로 나오므로 **녹색이 건너뛴 사실을 감추지 못한다** —
그냥 통과로 세면 그게 공허한 테스트다(교훈 2 재발).

### 9-3. 테스트 자신의 이식성 결함 — `/` 로 시작하는 인자 (T-E2 1건)

마지막 1건은 런처가 아니라 **테스트가 틀렸다**. `js` 헬퍼에 넘긴 단정식 `/egress/.test(…)` 는 첫 글자가 `/` 라
Git Bash 가 **POSIX 경로로 오인해 Windows 경로로 변환**한다(`C:/Program Files/Git/egress/.test(…)`) → `Function` 이 던져
단정이 **항상 거짓**이 된다. 같은 파일에서 `indexOf` 로 쓴 T-E3·T-E5 단정은 windows 에서도 통과했다.

**어떻게 알았나 — 실패 메시지에 관측값을 싣게 고쳐서 CI 왕복 한 번으로 특정했다.** 진단 출력이 보여 준 상태 JSON 은
`"degraded":"리뷰어 0종; egress: codex 제외(허용 밖); egress: agy 제외(허용 밖); egress: runtime-only — 반출 허용 리뷰어 0; …"` —
**17b·17c 는 windows 에서도 정확히 동작하고 있었다.** 단정만 깨져 있었다. 실패 메시지가 사실을 말하지 않으면 원인을 엉뚱한 곳에서 찾는다.

**이월(S5 이후):** ① 새 CI 스텝은 **그 스위트가 그 OS 에서 처음 도는 것**이다 — 신설 스텝의 첫 red 는 "구현이 틀렸다" 가 아니라
"전제·이식성·구현" 셋 중 무엇인지부터 가른다. ② 셸에서 프로그램 인자를 만들 때 **`/` 로 시작하지 않는다**(MSYS 경로 변환).
③ 단정 실패 메시지에 **관측값**을 싣는다 — OS 하나에서만 나는 실패는 재현 환경이 없어 로그가 유일한 증거다.
