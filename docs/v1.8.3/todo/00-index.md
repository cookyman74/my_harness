## 공통 규칙 (모든 단계에 적용 · req)

### R-1. 추측 금지 — 소스·실행 결과로 결정

- 파일·심볼·경로·행 번호는 **열어서 확인한 뒤** 쓴다. 설계서의 행 번호는 **2026-09-13~18 기준**이다 — 앞 단계가 파일을 바꿨으면 **다시 확인**한다(특히 `harness-intake.mjs`·`run-review.sh` 는 단계마다 줄이 밀린다).
- 확인하지 못한 것은 **"미실측"** 으로 적고 선검증 항목으로 올린다. 없는 것을 전제하지 않는다.
- 단계 문서의 「선검증」이 하나라도 **미통과면 착수하지 않는다**(`⛔ 착수 불가` + 사유·이월 위치).
- **작성자 보고를 그대로 믿지 않는다.** 하위 에이전트가 "반영했다" 고 해도 `grep -c`·`sed -n` 으로 확인한 뒤 체크한다(설계 검토 R25 에서 실제로 어긋난 적이 있다 — 원장 R26).

### R-2. 체크 표기 — **작업 하나가 끝날 때마다 즉시** 표시한다

| 표기 | 뜻 | 반드시 함께 적는 것 |
|---|---|---|
| `- [ ]` | 미착수 | — |
| `- [x]` | **완료** | 줄 끝에 ` — ✔ YYYY-MM-DD · <커밋 해시 7자 \| 미커밋> · 근거: <명령과 결과 한 줄>` |
| `- [~]` | **이월**(이 단계에서 하지 않기로 결정) | ` — ⏭ <사유> · 이월 위치: <단계·문서·줄>` |
| `- [!]` | **막힘**(전제가 깨져 진행 불가) | ` — ⛔ <무엇이 없어서 막혔나> · 해소 조건: <무엇이 되면 풀리나>` |

- **묶어서 나중에 채우지 않는다.** 항목 하나를 끝낸 그 자리에서 표시한다 — 세션이 끊겨도 다음 사람이 어디까지 됐는지 파일만 보고 안다.
- 근거는 **재현 가능한 한 줄**이다: 실행한 명령과 그 결과(예: `node --test tests/harness-intake/*.test.mjs` → `pass 574 fail 0`). "완료함" 같은 말은 근거가 아니다.
- 하위 항목이 있는 상위 항목은 **하위가 전부 `[x]`·`[~]` 가 된 뒤에** 체크한다.
- 단계 문서 제목 줄의 상태 뱃지와 [00-index 단계 목록 표](#단계-목록--상태)를 **같이** 갱신한다.

### R-3. 단계 완료 게이트 — **각 단계가 끝나면 외부리뷰를 진행한다**

단계는 아래 **다섯 가지가 모두 참일 때만** `✅ 완료` 다. 하나라도 빠지면 `🔍 외부리뷰중` 에 머문다.

1. 단계 문서의 **구현 체크리스트 전부 `[x]`**(또는 사유 있는 `[~]` 이월)
2. 단계 게이트 명령(테스트·정책 감사) **PASS** — 최소한 `bash skills/myharness/scripts/run-policy-audit.sh` 가 `fail 0`
3. **외부리뷰 수렴**(R-4 절차 · 아래 임계) — 또는 재실패 시 **축소 종료(사용자 승인)**
4. 결과서 `docs/v1.8.3/working_history/S{n}-<slug>.md` 작성 + `bash skills/myharness/scripts/check-artifacts.sh --file <결과서>` 끝줄 `ARTIFACTS: ok`
5. 커밋(순서: 리뷰 → 판정 → 수정 → 게이트 PASS → `check-artifacts.sh` → **사용자 승인** → 커밋). **push·태그는 매번 사용자 승인.**

**전 단계가 중대다**(팩토리 정본 변경 = 모든 생성 하네스로 전파). stabilizer 게이트로 닫는다 — 정책감사 · 외부리뷰 · 회귀 드라이런. 회귀 드라이런은 각 단계 문서의 게이트 항목에 둔다.

**수렴 임계(R-3 규칙):** R1~R9 는 **MED 이상** 대응 · **R10 부터는 HIGH 만** 대응하고 MED·LOW 는 이월 기록 · 종료는 **양 엔진 신규 HIGH 0 이 2연속**. `degraded` 가 비어 있지 않은 라운드는 **교차검증이 아니므로 연속 카운트에서 제외**한다(`external-review-loop.md:182`).

### R-4. 외부리뷰 절차 (단계 공통)

1. 프롬프트 2종을 `_workspace/reviews/{단계ID}_prompt_general.md`·`_prompt_perf.md` 에 먼저 쓴다. SCOPE·BASE·패치 경로를 명시한다.
2. 패치를 만든다: `git diff <BASE> -- <SCOPE 파일들> > _workspace/reviews/{단계ID}_diff.patch` · 트리 해시(`git diff … | git hash-object --stdin`)를 기록한다.
3. 실행: `REVIEWERS_OVERRIDE=codex REVIEW_TIMEOUT=1500 bash skills/myharness/scripts/run-review.sh {단계ID} claude` → 이어서 `REVIEWERS_OVERRIDE=agy … {단계ID}b claude`. **메모리 제약(16GB)으로 병렬 대신 포그라운드 순차**로 돈다.
4. **합산은 같은 트리에서만.** 두 리뷰어의 트리 해시가 다르면 그 라운드는 무효다 — 리뷰 중에는 SCOPE 파일을 **고치지 않는다**.
5. 판정은 **오케스트레이터가 소스로** 한다(위임 금지): 확인 / 부분 확인 / 이월 / 기각 — 기각은 반드시 실측 반박을 적는다.
6. 원장 `_workspace/evals/external-review/{단계ID}/…/verdicts.json` 에 라운드·지적·판정을 남기고, 수렴 시 `emit-loop-scorecard.sh` 로 측정 꼬리를 발행한다.
7. 리뷰어 실행 실패(타임아웃·쿼터)는 **1회 재실행**, 재실패면 단일 출처임을 명시하고 진행하되 **그 라운드는 수렴 카운트에서 뺀다**.

### R-5. 기록

- 결과서마다 `## 다음 단계 참조` 블록(미해결·핵심 결정과 이유·다음 단계). 다음 단계는 **직전 결과서의 이 블록을 먼저 읽고** 시작한다.
- 변경 이력: `docs/harness-history.md` 맨 위에 전문 행 → `CLAUDE.md` 「변경 이력」에 한 줄 요약(최근 5건 유지).
- 설계서와 어긋나는 결정을 하면 **설계서를 고치고** 그 사실을 결과서에 적는다. 계획서만 고치고 넘어가지 않는다.
