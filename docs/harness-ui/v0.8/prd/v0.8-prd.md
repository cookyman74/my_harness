## 1. 배경 — 앱의 진짜 목표와 현재의 반쪽

**이 앱의 목표(사용자 확정):** 코덱스·클로드·**제미나이(agy)** 등 여러 런타임의 에이전트 하네스를 사용자가 **한 곳에서 손쉽게 통합관리**(조회·진단·설치·업데이트·**편집**)하는 것.

**현재(v0.6~v1.5.1)의 반쪽:**
- **읽기**: F10에서 멀티런타임 읽기를 열었으나 대상이 `.claude`·`.agents`·`.codex` 3 dot-dir + CLAUDE/AGENTS/GEMINI.md 규칙파일까지. **Gemini 고유 경로(`.gemini/agents`·`.gemini/skills`)는 미편입**. 
- **편집**: F7 정의 편집기는 **Claude 정의만**(`.claude/agents/*.md`·`.claude/skills/*/SKILL.md`). **Codex/agy는 409(codex-only·edit-v0.7)** — 읽기전용. 즉 "통합관리"인데 편집은 한 런타임만.
- **런타임 경로 하드코딩**: `.claude`/`.codex`/`.agents` 경로가 `harness.ts`·`factory.ts`·`runtime.ts`·`harnesslist.ts` 등 **여러 곳에 흩어져 하드코딩** → 새 런타임 편입 = 다수 파일 수정(확장 비용 큼).
- **하네스 목록**: "오케스트레이터 + 고정 에이전트 팀"만 노출. 하네스가 *쓰는* **공용·서브 스킬**(예: external-review-loop)과 그 사용 관계(역인덱스)·orphan을 볼 곳이 없음.

**v0.8이 여는 것:** 런타임을 **플러그인처럼 추가**하는 어댑터 레지스트리 위에서 (1) Gemini까지 읽기 편입, (2) 공용·서브 스킬 관리 뷰, (3) **md-frontmatter 편집을 Claude+Gemini 동시** 개방(Gemini 에이전트가 Claude와 **동일 마크다운 포맷**이라 canonicalizer 재사용), (4) Codex TOML 편집, (5) 트리런타임 동기, (6) 런타임 인증·설치 통합.

> **핵심 발견(외부 조사·공식 문서 검증):** Gemini CLI(=agy 기반)는 리뷰 전용이 아니라 **완전한 호스트 런타임**이다. 에이전트 = `.gemini/agents/*.md`(**마크다운 + YAML frontmatter — Claude와 동일**), 스킬 = `.gemini/skills/` 또는 **`.agents/skills/` 별칭(Codex와 공유)** + `SKILL.md`, 규칙 = `GEMINI.md`, 자격 = `~/.gemini/oauth_creds.json`. 근거: [Gemini CLI Subagents](https://geminicli.com/docs/core/subagents/) · [Gemini CLI Skills](https://geminicli.com/docs/cli/skills/) · [github: docs/core/subagents.md](https://github.com/google-gemini/gemini-cli/blob/main/docs/core/subagents.md). **함의: Gemini 편입이 Codex보다 쉽다**(에이전트 포맷이 마크다운이라 TOML 작업 불요·`.agents/skills`는 이미 읽는 중).

## 3. 기능

### F12 — 런타임 어댑터 레지스트리 (foundation · 리팩터)
- **문제:** 런타임 경로·포맷이 여러 파일에 하드코딩 → 새 런타임 편입 = 다수 파일 수정·재작업·drift.
- **접근:** 단일 데이터 구동 레지스트리로 통합. 예:
  ```
  { id, label, agentsDir, agentExt, agentFormat("md-frontmatter"|"toml"),
    skillsDirs[], skillFormat("SKILL.md"), rulesFile, editable, installDest, authProbe }
  ```
  - claude: `.claude/agents/*.md`(md) · `.claude/skills/` · CLAUDE.md · editable · `~/.claude/skills/myharness`
  - codex:  `.codex/agents/*.toml`(toml) · `.agents/skills/` · AGENTS.md · (F15 후 editable) · installDest=**`$HOME/.agents/skills/myharness`(Gemini 공유·공식)**·폴백 `~/.codex/skills`(선검증 R8-j)
  - gemini: `.gemini/agents/*.md`(**md=Claude동일**) · [`.agents/skills/`, `.gemini/skills/`] · GEMINI.md · (F14 editable) · installDest=**`$HOME/.agents/skills/myharness`(Codex 공유)**·폴백 `~/.gemini/skills` · auth=`~/.gemini/oauth_creds.json`
  > **주의:** `agentFormat`이 schema까지 동일은 아님(F14 — 파서 공유·validator 런타임별). installDest 공유 경로는 F17 선검증(R8-j).
- **읽기·분류·편집 라우팅·팩토리 설치·인증 감지가 모두 이 레지스트리 순회.** 새 런타임 추가 = 항목 1개(로직 수정 0).
- **성공지표 S12:** 하드코딩 런타임 경로 0(전부 레지스트리 경유·회귀 테스트). 기능 동작 불변(순수 리팩터·기존 테스트 그린).

### F13 — 멀티런타임 읽기 확장 + 공용·서브 스킬 관리 뷰 (읽기전용)
- **문제:** ① Gemini 고유 경로 미편입. ② 하네스가 쓰는 공용·서브 스킬(external-review-loop 등)과 사용 관계·orphan을 볼 곳 없음.
- **접근:**
  - **Gemini 읽기 편입:** `readAgents`에 `.gemini/agents/*.md`, `readSkills`에 `.gemini/skills/` 추가(`.agents/skills`는 이미 읽음·별칭 우선순위 `.agents/skills` > `.gemini/skills` 반영). 런타임 태깅에 `gemini` 추가.
  - **공용·서브 스킬 섹션(`#/build`):** 스킬을 **분류**(오케스트레이터 / 공용 서브(≥1 하네스 사용) / **orphan**(미사용)) + **역인덱스**(스킬 → 사용 하네스). 서버 `listHarnesses` 확장으로 skill→harness 역맵 산출. **읽기·진단 전용** — 편집은 F14의 F7 딥링크.
- **성공지표:** S13a Gemini 에이전트/스킬이 인벤토리·하네스 목록에 런타임 배지와 함께 표시(측정: `.gemini` fixture e2e). S13b 공용 스킬의 사용 하네스 역인덱스·orphan 표시(측정: 역맵 단위 테스트).

### F14 — md-frontmatter 정의 편집 확장 (Claude + Gemini 동시)
- **문제:** F7 편집이 Claude 전용. Gemini 에이전트는 Claude와 **동일 마크다운 컨테이너**(md + YAML frontmatter)인데 막혀 있음.
- **접근:** F7 편집 대상에 **Gemini 에이전트(`.gemini/agents/*.md`)** + **공유/Gemini 스킬(`.agents/skills`·`.gemini/skills/*/SKILL.md`)** 편입. `resolveEditableAgent/Skill`·`safeDefPath` 화이트리스트에 해당 dot-dir 추가(정밀·per-seg). config-change 원장 `runtime` 태깅.
  - **정직화(R1 감사):** "동일 canonicalizer"는 **파서/직렬화(md+frontmatter 컨테이너) 재사용**까지만 참. **필드 스키마는 런타임별로 다름** → **런타임별 schema validator 분리**(Claude/Gemini 각 required/optional·미지 필드 보존). 파서 0작업, validator는 런타임당 소량.
- **심링크-편집 정책(R1 감사·모순 해소):** F17이 심링크 설치를 쓰므로 편집 대상이 심링크일 수 있음. 정책: **편집은 "실파일"만.** 대상이 심링크면 → 링크 타깃을 resolve, **타깃이 projectRoot 내 신뢰 경로면 그 실파일을 편집**(딥링크 리다이렉트), **밖이면 거부**(`edit-symlink-out-of-root`). 즉 F14 보안(심링크 최종파일 거부)은 유지하되, **신뢰 타깃 리다이렉트**로 F17 심링크 설치와 공존.
- **핵심 보안(A184 상세):** 새 쓰기 경로마다 **per-segment `lstat`(중간 dir 심링크 거부)·root `realpath` containment·dirfd/openat 스타일 해소·최종 파일 심링크 금지·O_NOFOLLOW·temp 동일 dir·rename 전후 inode/root 재검증·hardlink 카운트 정책·원자쓰기·낙관적 동시성·게이트(definitionEditEnabled)**. 화이트리스트는 리터럴 dot-dir만(traversal 불가·TOCTOU 방어).
- **성공지표 S14:** Claude·Gemini 에이전트/스킬을 F7로 편집·롤백·**런타임별 스키마 검증 통과분만 저장**(측정: 편집 e2e·미지/필수 필드 fixture·경로안전 외부감사 no-high). 화이트리스트 밖·심링크-out-of-root 쓰기 거부.

### F15 — Codex TOML 정의 편집
- **문제:** Codex 에이전트는 `.codex/agents/*.toml`(TOML) — 현 canonicalizer(md-frontmatter 전용)로 편집 불가.
- **접근:** **TOML canonicalizer + differential 파서** 신설 — **AST 기반 파싱**(정규식 금지)·라운드트립·주석 보존·**엄격 검증**. F7에 Codex 에이전트 편입. (Codex 스킬은 `.agents/skills`·SKILL.md라 F14에서 이미 열림.)
- **핵심 보안(R1 감사·TOML injection):** UI 입력 → 서버 `.toml` 작성 시 **injection 방어**: 문자열 이스케이프 엄격·**duplicate key fail-closed**·dotted-table shadowing 거부·**미지 특권 필드 preserve-only 또는 명시 확인**·멀티라인 프롬프트 주입 무해화·생성 diff에 **effective semantic diff** 포함(구조 변화 가시화).
- **성공지표 S15:** Codex TOML 에이전트 편집·검증·롤백(측정: TOML differential·injection fixture·중복키/구조변조 fail-closed·외부감사). 손상/악의 TOML fail-closed.

### F16 — 트리런타임 동기 편집 (drift 방지)
- **문제:** 한 스킬이 여러 런타임 경로에 **실사본**으로 존재할 수 있음(`.claude/skills` ↔ `.agents/skills` ↔ `.gemini/skills`). 한쪽만 편집하면 drift.
- **정책 확정(R1 감사·기본값 못박음):**
  - **심링크 사본은 동기/drift 대상 제외** — 같은 inode(물리 동일)라 정본 1회 편집=전 링크 반영(자동). drift는 **실사본(별 inode)만** 발생.
  - **기본 = drift 경고 + 명시적 다중타깃 apply**(자동 동기 아님). 사용자가 대상 런타임을 체크한 경우에만 그 실사본들에 적용.
  - **자동 동기는 심링크-정본 관계에서만**(물리 동일이라 이미 동기·추가 쓰기 0). 실사본 자동 동기 금지(무단 덮어쓰기 방지).
  - SSOT·동시편집 stale: 각 사본은 독립 pathId·baseHash → 다타깃 apply는 대상별 낙관적 동시성(한 사본 stale이면 그 사본만 409).
- **성공지표 S16:** 심링크 사본 drift 제외 확인·실사본 drift 감지·기본 경고+명시 다타깃 apply·무단 부분/자동 동기 없음(측정: 심링크 vs 실사본 fixture).

### F17 — 런타임 설치·인증 통합 운영 (설치 매트릭스 · 정본1-링크N)
- **문제:** "myharness를 Claude·Codex·Gemini 중 어디에·모두 설치할지"를 한 곳에서 결정·운영할 수단이 없음. F11 팩토리는 Claude·Codex 개별 카드뿐(매트릭스·벌크·drift 통합 부재). agy 인증은 "조회 미지원"(v1.5.1)에 머묾. Ops가 런타임 부분 표시.

- **운영 원리(정본1-링크N):** myharness 정본 = `skills/myharness/` **한 곳**(교리). 각 런타임 설치 = 그 정본을 가리키는 **심링크**를 런타임 스킬 dir에 거는 것. **"어디에 설치?" = "어느 런타임에 링크?"** — 심링크라 정본 1회 갱신 → 링크 건 전 런타임 자동 최신.

- **설치 채널 2개(기본 가정 · 선검증 대상):** 공식 문서상 `.agents/skills`는 **Codex·Gemini 공유** 경로 → 채널이 3개가 아니라 **2개로 접힌다는 것이 기본 가정**. 단 유저-레벨 공유는 **F17 착수 전 실환경 선검증**(R8-j) — 미작동 판명 시 런타임 개별 3채널로 폴백(구조 유연). 아래는 기본 가정:
  | 채널 | 경로 | 커버 |
  |------|------|------|
  | **A. Claude** | `~/.claude/skills/myharness` 또는 marketplace 플러그인 | Claude |
  | **B. 공유** | 워크스페이스 `.agents/skills/myharness` · 유저 `$HOME/.agents/skills/myharness` | **Codex + Gemini** |
  → 공식 문서 확정(R1 감사): Codex repo 스킬=`.agents/skills`·전역=`$HOME/.agents/skills` / Gemini 워크스페이스=`.agents/skills`(별칭)·유저=`~/.agents/skills`(별칭). **즉 `.agents/skills`는 워크스페이스·유저 **둘 다** Codex·Gemini 공유** → `.agents/skills/myharness` 링크 1개가 두 런타임 동시 커버(워크스페이스·유저 각각). (구 `~/.codex/skills`·`~/.gemini/skills`는 런타임 고유 폴백 경로 — 공유 미작동 시 폴백, F17서 실검증.)

- **접근:**
  - **설치 매트릭스 UI(Factory 확장):** 런타임 × {감지·상태·버전/동기·액션} 매트릭스 + **벌크 [감지된 전체 설치]·[전체 동기]·[전체 제거]**. 채널 B는 "Codex+Gemini(공유)" 한 행으로 묶어 표기(링크 1개=2런타임 명시).
  - **감지 기반 추천:** CLI/config dir 있는 런타임만 설치 후보 활성. **미감지 런타임엔 설치 권유 안 함**(오설치 방지·회색). 기본 권장 = **"감지된 전체 · 심링크"**(한계비용 0·정본 1개·업데이트 1회로 전 런타임 최신).
  - **drift 통합:** 정본 버전 vs 각 링크 대조. 심링크=자동 동기, 복사/marketplace 구버전=`동기 필요` 배지 → **[전체 동기]** 일괄.
  - **방식별 정책(F11 재사용):** 심링크(기본·권장) / 복사(Windows 폴백·각각 재설치) / marketplace(Claude 전용·앱 미수정·`/plugin update` 안내·심링크와 택1·중복 감지).
  - **부분 성공 허용:** "전체 설치"=all-or-none 아님 → 런타임별 결과 보고(F11 낙관 캐시 패치·백업·원복 UX 재사용). 한 런타임 실패가 나머지 안 막음.
  - **agy 인증 실감지:** `~/.gemini/oauth_creds.json`(+`google_accounts.json`) 존재로 **"인증됨(설정 감지)"** 승격(파일 근거·600 존중·내용 미판독). 부재 시 "미인증".
  - **Ops 통합:** 등록 런타임 전부(claude·codex·gemini) 설치·버전·인증(감지 근거) 일관 표시.

- **스코프(혼동 방지):** factory install = **스킬 링크만.** 규칙파일 포인터(CLAUDE/AGENTS/GEMINI.md)는 *생성 하네스* 진입점이지 factory install 대상 아님(비목표).

- **성공지표:** S17a 설치 매트릭스에서 런타임별·전체 설치/동기/제거가 감지 기반으로 동작·부분성공 보고(측정: 3런타임 fixture·벌크 e2e). S17b `.agents/skills` 링크 1개가 Codex·Gemini 둘 다 커버(측정: 공유 채널 검증). S17c agy 인증이 oauth_creds 근거로 정직 표시(측정: 유무 fixture). S17d drift(정본 vs 링크) 감지·전체 동기(측정: 구버전 복사본 fixture).

## 5. 비목표 (v0.8 범위 밖 · 명시)

- **런타임 정의의 자동 상호 변환**(예: Claude 에이전트 → Codex TOML 자동 포팅). 편집은 각 포맷 그대로. (팩토리 생성은 별개 — myharness 소관.)
- **agy를 대화형 실행·supervised run 호스트로**(agy는 리뷰 + 이제 정의 관리 대상 런타임 · 실행 supervise는 v0.5 supervisor 경계 그대로).
- **oauth_creds.json 내용 판독·토큰 표시**(존재·권한만 근거 · 비밀 미판독·미표시).
- **전역 사용자 스킬(`~/.gemini/skills`·`~/.claude/skills`) 편집을 기본 노출** — 프로젝트 스코프 우선(전역은 팩토리 설치 경로라 F11/F17 별도 관리).
- **새 런타임(기타 에이전트) 즉시 편입** — 레지스트리로 준비하되, 각 런타임은 **호스팅 규약(경로·포맷·자격) 확인 후** 항목 추가(가정 위 구현 금지).
- **규칙파일 포인터(CLAUDE/AGENTS/GEMINI.md) 자동 등록** — 이는 *생성 하네스* 진입점 소관(myharness). factory install(F17)은 **스킬 링크만** 관리(혼동 방지).
- **미감지 런타임 강제 설치** — CLI/config 없는 런타임엔 설치 권유·강제 안 함(오설치 방지).
