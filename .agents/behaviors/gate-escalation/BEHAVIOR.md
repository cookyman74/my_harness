## Intent

팩토리 정본(`skills/myharness/`) 변경은 **모든 생성 하네스에 전파된다** — 되돌리려면 각 하네스에서
`harness-update.sh` 를 다시 돌려야 한다. 그래서 게이트 강도는 파일 위치가 아니라 **전파 반경**으로
정한다.

- **중대** — `skills/myharness/` 본문·`references/`·`scripts/`. 정책감사 + 외부리뷰 + 회귀 드라이런 3층.
- **표준** — 이 레포에만 머무는 문서·설정. 정책감사 + 내부 QA.
- **경량** — 오탈자·서식. 정책감사만.

무차별 게이트는 과의식이다. 등급을 올리는 근거는 "혹시 몰라서"가 아니라 **전파 여부**다.

## Evidence

판단은 실행 결과로 한다. 산문 보고가 아니라 종료코드와 출력이다.

- `run-policy-audit.sh` — `POLICY AUDIT: PASS (fail N, warn M)`
- `check-review-tools.sh` — `REVIEWERS:` 와 `SHADOWED:` 두 줄을 **모두** 읽는다
- 회귀 드라이런 — `tests/*.sh` 종료코드
- 외부리뷰 — `verdicts.json` 원장(산문 판정이 아니라)

## Decision

세 층이 **모두** 통과해야 정본 변경을 승인한다. 하나라도 미실행이면 "통과"가 아니라 **미판정**이다.

## Execution

skill-maintainer 의 diff 를 받아 등급을 매기고, 등급에 맞는 게이트를 순서대로 돌린 뒤
`_workspace/{phase}_stabilizer_gate.md` 에 층별 결과를 남긴다. 통과분만 승인 관문으로 보낸다.

## Recovery

- 정책감사 스크립트가 없거나 실패하면 **사유를 명시하고** 외부리뷰만으로 진행한다(감사 생략을 기록).
- 외부 리뷰어가 없거나 축소되면(`REVIEWERS: none`·`SHADOWED:`) 게이트를 정책감사+내부 QA 로 줄이고
  **축소 사실을 보고서에 적는다**. 축소 라운드를 "양 엔진 통과"로 적지 않는다.
- 1회 재시도 후 재실패면 그 게이트 결과 **없이** 진행한다. 상충 데이터를 삭제하지 않는다.

## Failure modes

- **검사가 도는 것처럼 보이지만 안 돈다.** `command -v` 실패를 "미설치"로만 처리하면 PATH 밖에 설치된
  리뷰어가 조용히 탈락하고, 결과서에는 "양 엔진"이라 적힌다. 실측으로 확인된 재발 계열이다.
- **행정적 기록으로 기술적 실패를 대체한다.** 문서에 "미적용"이라 적는 것은 스크립트가 0 아닌 코드로
  죽는 것을 막지 못한다. 기술적 대응이 먼저다.
- **측정했다는 거짓 신호.** 원장이 비었는데 집계가 0 으로 나오고 경고가 없으면, 측정을 건너뛴 것보다
  나쁘다 — 스킵은 부재가 드러나지만 이건 통과로 읽힌다.
- **월권.** 게이트 조율·판정만 한다. 스킬 본문 수정은 skill-maintainer, 문서 동기는 doc-syncer 소관이다.
