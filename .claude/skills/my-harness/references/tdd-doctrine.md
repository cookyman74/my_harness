# TDD 교리 (Red → Green → Refactor + Tidy First)

생성된 빌더/수정/QA 에이전트의 작업 원칙에 주입하는 표준 교리. Kent Beck TDD + Tidy First 기반. external-review-loop Step 5의 수정 규율이 이 문서를 따른다.

## TDD 사이클
1. **Red** — 가장 단순한 실패 테스트 먼저. 동작을 설명하는 이름(`shouldSumTwoPositiveNumbers`). 실패가 명확하게.
2. **Green** — 통과시킬 **최소** 코드만. 그 이상 금지.
3. **Refactor** — 통과 상태에서만. 한 번에 하나씩, 매 단계 후 테스트 재실행. 중복 제거·명료성 우선.

매번 한 테스트씩 → 통과 → 구조 개선. 항상 전체 테스트 실행(장기 테스트 제외).

## Tidy First — 구조/행위 분리
변경을 2종으로 엄격 분리:
- **구조 변경(structural)**: 동작 불변 — 리네임·추출·이동.
- **행위 변경(behavioral)**: 기능 추가/수정.

규칙:
- 한 커밋에 구조+행위 **혼합 금지**.
- 둘 다 필요하면 **구조 먼저**.
- 구조 변경이 동작을 안 바꿨음을 전후 테스트로 검증.

## 커밋 규율
커밋 조건(전부 충족 시에만):
1. 모든 테스트 통과
2. 모든 컴파일러/린터 경고 해소
3. 단일 논리 단위
4. 커밋 메시지에 구조/행위 여부 명시

작고 잦은 커밋 > 크고 드문 커밋. (단 에이전트는 커밋·브랜치 금지 — 오케스트레이터가 게이트 후 단일 커밋.)

## 코드 품질
중복 박멸 · 이름과 구조로 의도 표현 · 의존성 명시 · 작고 단일책임 메서드 · 상태/부수효과 최소 · 가능한 가장 단순한 해법.

## 주입 방법
에이전트 정의 `## 작업 원칙`에 한 줄(**실경로** — 서브에이전트는 `[[ ]]` 미해소): `> TDD 규율: \`.claude/skills/my-harness/references/tdd-doctrine.md\` 준수 (Red→Green→Refactor, 구조/행위 커밋 분리).` 본문 복붙 금지 — 경로 포인터만(DRY).
