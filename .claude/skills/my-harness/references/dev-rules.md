# 개발 규칙 (생성 에이전트 작업 원칙 주입용)

LLM 코딩 흔한 실수를 줄이는 행위 가이드. 생성된 모든 빌더/수정 에이전트의 `## 작업 원칙`에 주입한다. **주의:** 글로벌 `~/.claude/PRINCIPLES.md`(KISS/YAGNI/SOLID)와 개념이 겹친다 — 이 문서의 가치는 *생성되는 에이전트 산출물에 규칙을 전파*하는 데 있다. 글로벌이 적용되는 메인 컨텍스트와 달리, 서브에이전트는 이 포인터가 없으면 규칙을 못 받는다.

**트레이드오프:** 속도보다 신중. 사소한 작업엔 판단껏.

## 1. 코딩 전 사고
가정하지 말고, 혼란 숨기지 말고, 트레이드오프 드러내라.
- 가정은 명시. 불확실하면 질문.
- 해석이 여럿이면 제시 — 말없이 하나 고르지 마라.
- 더 단순한 길 있으면 말하라. 정당하면 반론.
- 불명확하면 멈추고 무엇이 헷갈리는지 말하고 질문.

## 2. 단순성 우선
문제를 푸는 최소 코드. 투기적 코드 금지.
- 요청 외 기능 없음.
- 단일 사용처에 추상화 없음.
- 요청 안 한 "유연성/설정 가능성" 없음.
- 불가능 시나리오용 에러 처리 없음.
- 200줄을 50줄로 줄일 수 있으면 다시 써라.
- 자문: "시니어가 과설계라 할까?" → 그렇다면 단순화.

## 3. 외과적 변경
필요한 것만 건드려라. 네가 만든 것만 치워라.
- 인접 코드/주석/포맷 "개선" 금지.
- 안 망가진 것 리팩토링 금지.
- 다르게 하고 싶어도 기존 스타일 따르라.
- 무관한 죽은 코드는 언급만 — 삭제 금지.
- 네 변경이 만든 고아(import/변수/함수)만 제거. 기존 죽은 코드는 요청 시만.
- 테스트: 바뀐 모든 줄이 요청에 직접 추적되는가.

## 4. 목표 주도 실행
성공 기준 정의 → 검증될 때까지 반복.
- "검증 추가" → "잘못된 입력 테스트 작성 후 통과시킨다"
- "버그 수정" → "재현 테스트 작성 후 통과시킨다"
- "X 리팩토링" → "전후 테스트 통과 보장"
- 다단계 작업은 간단 계획: `[단계] → 검증: [확인]`.

## 주입 방법
에이전트 정의 `## 작업 원칙`에 한 줄(**실경로** — 서브에이전트는 `[[ ]]` 미해소): `> 개발 규칙: \`.claude/skills/my-harness/references/dev-rules.md\` 준수 (사고 우선·단순성·외과적 변경·목표 주도).` 본문 복붙 금지 — 경로 포인터만(DRY).
